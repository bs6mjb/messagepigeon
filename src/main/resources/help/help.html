MessagePigeon Help

MessagePigeon lets you look at, edit, back up and restore the messages on IBM MQ queues without writing any code. Browsing a queue is always safe: it reads messages without removing them. Anything that changes a queue asks you first.

1. Getting started

  1. Click + New Profile at the bottom of the sidebar and fill in the queue manager details (see Connection profiles). Click Save.
  2. Right-click the profile and choose Open Queue... (or double-click it).
  3. Type the queue name and click OK. MessagePigeon connects (asking for the password if you did not save one) and shows the queue's messages in a new tab.
  4. Double-click a message to read or edit it.

2. The main window

  • Sidebar (left) lists your profiles. A green dot means connected, amber means connecting, grey means not connected. Hover over a profile to see its host, queue manager and channel.
  • Tabs (right): every queue you open gets its own tab, named QUEUE [profile]. You can have many queues open at once, on one queue manager or several. Click the × on a tab to close it.
  • Menu bar has File, Queue and Help (see Menus and keyboard shortcuts).
  • Icon bar under the menu bar has a button for each of the common menu actions: new profile, open queue, disconnect, refresh, close tab, insert, add from file, add from folder, export, import, delete selected, delete all, and help. Hover over a button to see what it does and its keyboard shortcut. Buttons that work on a queue are faded until a queue tab is open. Every menu item, and every item on the right-click menus, has a matching icon.

The profile menu

Right-click a profile in the sidebar:

ItemWhat it does

Connect / DisconnectConnects without opening a queue, or closes the connection and all of its tabs.

Edit Profile...Changes a profile. If it is connected you are asked to disconnect first.
Duplicate ProfileMakes a copy named "name (copy)", handy for a similar queue manager or channel.
Export Profile to File...Saves just this profile to a file (see Sharing profiles).

Right-clicking empty space in the sidebar offers just New Profile....

3. Connection profiles

A profile holds everything needed to reach a queue manager. The fields, in order:

FieldMeaning
Profile nameThe label shown in the sidebar.
Queue managerThe queue manager's name, for example QM1. Required.
HostThe machine the queue manager's listener runs on. Required.
PortThe listener port, usually 1414. Digits only, from 1 to 65535.
ChannelThe server-connection (SVRCONN) channel to use. Required.
User ID / PasswordOptional. Leave both blank if the channel does not need a login.
Use TLS and the fields below itSee Secure connections.

Passwords

Passwords (the connection password and the key store and trust store passwords) are never saved as plain text. They are encrypted with AES-256-GCM, using a random key created on first run and stored in a file that only your Windows account can read. Be aware that this does not protect against someone who can already read your whole profile folder as you, because the key sits beside the data.

If you leave the connection password blank for a profile that has a User ID, MessagePigeon asks for it each time you connect and does not save it.

Sharing profiles

File > Export Profiles to File... saves all your profiles to a text file (or use Export Profile to File... on a profile's right-click menu for just that one). File > Import Profiles from File... adds the profiles in such a file to your list.

  • No passwords are ever written to the file - not the connection password and not the key store or trust store passwords, not even encrypted. Your queue history is left out too.
  • After an import you are asked for the user password when you connect. If the profile uses key store or trust store passwords, add them with Edit Profile.... Key store and trust store paths are copied as they were, so change them if the files live elsewhere on the other machine.
  • An imported profile whose name is already in use is renamed, for example "Dev QM (2)". Nothing existing is replaced.

4. Secure connections (TLS)

Tick Use TLS to enable the TLS fields:

  • TLS protocol: TLSv1.2 or TLSv1.3.
  • Cipher suite: choose one from the list or type one. Use Java (JSSE) names such as TLS_AES_256_GCM_SHA384 (TLS 1.3) or TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384 (TLS 1.2). If you leave it blank a sensible one is chosen to match the protocol. The channel on the queue manager must allow it.
  • Peer name (DN): optional. If given, the queue manager's certificate must have a matching distinguished name.
  • Key store: your client certificate and private key, needed only when the channel requires a client certificate (mutual TLS).
  • Trust store: the certificate (or its certificate authority) that vouches for the queue manager's own certificate. Almost always required.

Key stores and trust stores can be PKCS12 (.p12, .pfx), JKS (.jks) or JCEKS. The type is filled in for you from the file extension when you choose the file; you can still change it. Each store has its own password. The file chooser behind each ... button opens in the folder of the file already in that box, otherwise in the folder you last browsed in (so after picking the key store, the trust store chooser starts in the same place).

5. Opening and browsing a queue

Opening a queue reads its messages without removing them. If the queue is already open in a tab, that tab is selected and refreshed instead of opening a second one.

The tab's title shows how many messages the grid holds, for example ORDERS (12). If Max messages is cutting the list short it reads ORDERS (1000 of 2500). It updates each time the queue is read.

Queue history

The Open Queue box remembers the last 20 queue names you opened, separately for each profile, so a profile only ever offers its own queues. Pick one from the drop-down or type a new name.

To tidy the list, right-click the profile and choose Queue History.... A window opens with a grid of that profile's remembered queues, most recent first:

  • Highlight one or more rows (hold Ctrl or Shift for several) and click Remove Selected, or press the Delete key, to forget just those queues.
  • Click Clear All... to forget every queue for the profile, after you confirm.

Changes are saved straight away. This only forgets names in MessagePigeon; it never touches the queue manager or the queues.

Working with the queue

Each queue tab has one setting of its own, at the top: Max messages, how many messages to read, oldest first (default 1000). Press Enter in the box, or click Refresh, to apply a new value. The status bar tells you when the queue holds more messages than you are showing.

Everything else is done with the icon bar, the Queue menu or the right-click menu, and always acts on the tab you are looking at:

ActionWhat it does
RefreshReads the queue again.
Insert Message...Adds one message that you type (see Adding messages).
Add From File...Adds one message per line of a text file.
Add From Folder...Adds one message per file in a folder, optionally only certain file types, in name or date-modified order.
Export to File...Writes every message on the queue to a file.
Import from File...Puts the messages from an export file onto the queue.
Delete Selected...Removes the highlighted messages.
Delete All Messages...Empties the queue.

While one of these is running, starting another is refused with a note in the status bar; wait for it to finish.

The message grid

Each row is a message. Columns: sequence number, put date and time, Message ID, format, persistence, priority, size in bytes, and a one-line preview of the text. Click a column heading to sort. Hold Ctrl or Shift to highlight several rows.

The pane below the grid is a read-only viewer for the highlighted message. It shows the headers, and the data with the same View as choices as the message window: Text (the default), XML, JSON, Tree and Hex. XML, JSON and Tree are offered only when the message really is XML or JSON, and are greyed out otherwise. The view you pick is remembered as you click from message to message; if a message cannot be shown that way (for example you chose XML but the next message is plain text), it is shown as Text until you reach one that can. To change a message, double-click it to open the message window. With several rows highlighted, the pane just says how many are selected.

The status bar shows the queue's depth and how many messages are displayed.

The order shown is the order the queue manager would deliver messages: highest priority first, then oldest first.

Right-click a message

  • View / Edit Message... (one message highlighted): opens the message window.
  • Export Selected to File...: writes only the highlighted messages to a file.
  • Delete Selected...: removes the highlighted messages.
  • Select All.

Double-clicking a row also opens the message window.

6. Viewing and editing a message

Double-click a message to open its own window. The top shows every header: Message ID, Correlation ID, put time, format, CCSID and encoding, size, who put it and from which application, persistence, priority and the reply-to queue and queue manager. Persistence, priority and the two reply-to fields can be changed.

View as

The window always opens on Text. Choose another view with the buttons above the data:

ViewShows
TextThe message as plain text. This is the only view you type in.
XMLIndented, colour-coded XML. Available only when the text is well-formed XML.
JSONIndented, colour-coded JSON. Available only when the text is valid JSON.
TreeA collapsible tree of the XML or JSON, good for large messages.
HexA hex dump of the bytes, with an ASCII column.

The XML, JSON and Tree choices are greyed out when the text does not qualify. They re-check as you edit, so they switch on as soon as your text becomes valid. Format text re-indents XML or JSON in the editor itself.

Saving your changes

  • Save to Queue replaces the original message with your edited version. MQ cannot change a message in place, so MessagePigeon removes the original and puts the edited one back as one all-or-nothing step: if anything goes wrong the queue is left exactly as it was. The edited message keeps the original's Message ID, but it joins the queue behind other messages of the same priority and gets a new put time. If someone else removed the original in the meantime, nothing is changed and you are told.
  • Put as New Message adds your edited version as a new message and leaves the original alone.
  • Close asks before discarding unsaved edits.

Binary messages (content that is not valid text) are shown read-only, with a warning, so that editing cannot corrupt them. Use the Hex view to inspect them. Unedited messages are always written back with their exact original bytes.

7. Adding messages

  • Insert Message... opens a box to type or paste the message text. You can also choose persistent or non-persistent, a priority from 0 to 9, and a reply-to queue.
  • Add From File... reads a plain text file (UTF-8) and puts one message per line. Blank lines are skipped, and you see the count and confirm before anything is added. A MessagePigeon export file is refused here: use Import from File for those.
  • Add From Folder... asks you to choose a folder and puts one message per file, with the whole file as the message. This is the way to add messages that run over several lines, such as XML or JSON documents. Before anything is added, a window lets you narrow down and order the files:
    • File types: type one or more extensions, separated by commas or spaces (for example xml, json; a leading dot or *. is fine and case is ignored), to add only those files. Leave it empty to add every file. The window shows at once how many files match, their total size, and which would go first and last.
    • Order: File name (A to Z, ignoring case, the default), Date modified, oldest first, or Date modified, newest first. Files with the same modified time fall back to name order. The order is the order the messages are put on the queue, and so the order they are delivered in. The window remembers your choices for the rest of the session.
    • The Add button is greyed out when no file matches, or when a file or the total is over MQ's limits.
    • Only the files directly in the folder are used. Subfolders, hidden files and empty files are skipped.
    • A file that is UTF-8 text becomes a text message (a leading byte order mark is dropped). Any other file, such as an image or a zip, is added as raw bytes with no format.
    • One message can be at most 100 MB (MQ's own limit), and one batch at most 256 MB. The file name is not stored in the message.

Large additions are committed in batches of 500; if there is an error, the current batch is rolled back.

8. Exporting and importing

An export is a plain text file you can open in any editor. Use it to keep a copy of a queue before you change it, to move messages between queues or queue managers, or to read messages offline.

  • Export to File... (icon bar or Queue menu) writes all messages on the queue. It does not remove them.
  • Export Selected to File... (right-click a highlighted group of messages) writes only those messages.
  • Import from File... reads an export file and adds its messages to the queue you are looking at. It does not clear the queue first.

Progress

Reading a queue into the grid (opening it, or Refresh) shows the same bar with a counter, for example "Reading messages: 340 of 1000", which matters when the messages are large.

Exporting, importing and the two Add From File / Folder actions show a progress bar and a running count at the bottom of the tab, for example "Adding messages: 800 of 1200". The last step, "Committing", is MQ making the new messages permanent. Messages are added in batches of 500, each committed as it completes, so a very large import never sits in one huge unit of work. If something fails part-way, the batch in progress is backed out, but batches already committed stay on the queue, so check the depth and re-run what is missing.

The file format

Each message is a block of name: value header lines, a line containing ---, the message text exactly as it was on the queue, and an end line:

=== MESSAGE 1 ===
format: MQSTR
ccsid: 1208
persistence: persistent
priority: 5
correlId: 000000000000000000000000000000000000000000000000
msgId (info): 414D5120514D31...
boundary: === END OF MESSAGE ===
---
{"orderId": 1001, "amount": 249.99}
=== END OF MESSAGE ===
  • You can edit the message text or the header values before importing. Lines marked (info) (Message ID, put time and so on) are ignored on import.
  • Imported messages get new Message IDs, because MQ assigns them.
  • Binary messages are written as Base64 and marked data-encoding: base64, so nothing is lost.
  • If the text itself contains the end line, the writer lengthens it so the file still reads back correctly.
  • The first line of the file must be #MESSAGEPIGEON-EXPORT-V2; anything else is refused.

9. Deleting messages

Deleting removes messages from the queue permanently. Do an Export to File first if you might want them back.

  • Delete Selected... (icon bar, Queue menu or right-click): removes the highlighted messages after you confirm. Each is matched by its Message ID, so a message that has already gone is simply skipped.
  • Delete All Messages...: removes every message on the queue. To avoid accidents a box asks you to type the queue name to confirm. If what you type does not match the queue name (stray spaces at either end are ignored), you are told so and nothing is deleted.

You need the right MQ authority for each action: browse and inquire to look at a queue, get to delete or replace a message, and put to add one. Delete All removes messages one at a time, so it needs get authority rather than clear authority.

11. Starting the program (the exe and Java)

MessagePigeon needs Java 21 or later. MessagePigeon.exe (kept next to messagepigeon.jar) starts the program and looks for a suitable JDK automatically, in this order:

  1. the folder you chose last time,
  2. the JAVA_HOME environment variable,
  3. the PATH,
  4. the places installers record Java in the registry,
  5. the usual install folders under Program Files.

Each is checked and anything older than Java 21 is skipped. If none is found, a window asks you to choose the JDK folder (the one JAVA_HOME would point to, for example C:\Program Files\Java\jdk-21). The folder is checked, remembered, and used from then on. To be asked again, delete java-path.txt (see Where settings are kept).

You can also run the jar directly with java -jar messagepigeon.jar.

IBM's MQ client library

IBM licenses its MQ client library (com.ibm.mq.allclient.jar) itself, so it is not included with MessagePigeon: you supply your own copy. It is in the java\lib folder of an IBM MQ installation, in IBM's MQ redistributable client, and on Maven Central; IBM's licence terms apply to your copy.

At start-up the program looks for it in this order and uses the first valid one: a copy named with -Dmessagepigeon.mqjar=<path> or the MESSAGEPIGEON_MQ_JAR environment variable; the one you chose last time; a lib folder (or the same folder) next to the program; an IBM MQ installation. If none is found, it explains what is needed and asks you to locate the file. It checks that the file really is IBM's client before remembering it.

If the file is moved or deleted, the next start tells you that the copy it was using can no longer be used and asks you to locate it again. To switch to a different copy at any time, use Help > IBM MQ Client Library...; the change applies the next time the program starts. The About window shows which copy is in use.

12. A local test queue manager

The project includes a ready-made IBM MQ queue manager in Docker for safe experimenting. See docker\README.md in the project folder. In short: run generate-certs.ps1 and setup-env.ps1 once, then docker compose up -d. It provides queue manager QM1 on localhost:1414, a plain channel PIGEON.PLAIN.SVRCONN, a TLS channel PIGEON.TLS.SVRCONN, and the queues PIGEON.TEST.QUEUE.1 and PIGEON.TEST.QUEUE.2.

13. Troubleshooting

When something fails, the message shows the MQ reason code and its name, and any underlying cause. Common ones:

CodeNameUsual cause and fix
2538HOST_NOT_AVAILABLECannot reach the host and port. Check the spelling of the host, the port, that the queue manager's listener is running, and any firewall.
2059Q_MGR_NOT_AVAILABLEThe queue manager is not running, or is not reachable on that port.
2058Q_MGR_NAME_ERRORThe queue manager name does not match the one on that host and port.
2540UNKNOWN_CHANNEL_NAMEThe channel does not exist. Check its name (it is case-sensitive).
2537CHANNEL_NOT_AVAILABLEThe channel exists but refused the connection, often because of channel authentication rules or a TLS mismatch. The queue manager's error log says why.
2035NOT_AUTHORIZEDWrong user or password, or the user lacks authority for the queue manager or the queue.
2085UNKNOWN_OBJECT_NAMEThe queue does not exist. Check the name and its capital letters.
2393 / 2397 / 2400SSL / JSSE / cipher errorsTLS problems. Check that the cipher suite matches the channel's, the trust store holds the queue manager's certificate, the store password and type are right, and the protocol is allowed.
2009CONNECTION_BROKENThe connection dropped. Disconnect and connect again.
  • "Keystore was tampered with, or password was incorrect": the store password is wrong, or the store type does not match the file. Check both.
  • The XML, JSON or Tree view is greyed out: the text is not well-formed XML or valid JSON, so there is nothing to format.
  • Fewer messages than expected: raise Max messages and press Refresh.
  • The window did not start from the exe: no Java 21+ was found or chosen. Delete java-path.txt and start again to choose a JDK folder.
  • "MessagePigeon needs IBM's MQ client library" at start-up: no usable copy was found, or the one you chose was moved or deleted. Click OK and locate com.ibm.mq.allclient.jar again.
  • "A library that IBM's MQ client needs is missing": the copy in use is incomplete. Use a full copy (for example the one from an IBM MQ installation) via Help > IBM MQ Client Library... and restart.

14. Where settings are kept

Everything is in the .messagepigeon folder inside your Windows user folder:

FileContents
profiles.propertiesYour connection profiles, with passwords encrypted.
secret.keyThe key used to encrypt those passwords. Keep it with the profiles; without it, saved passwords cannot be read and you would be asked for them again.
java-path.txtThe JDK folder chosen in the exe's start-up prompt.
